How trade-offs are presented: For each decision area, Claude lists 2–3 concrete options with one-line trade-offs, gives a labeled recommendation with reasoning, and waits for your choice before moving to the next area. You are never asked to pick from a blank slate.
S·02
Output — Context Files
What gets generated and why each file exists separately
+
P
.claude/steering/product.md — project purpose, users, interaction model, what success looks like
T
.claude/steering/tech.md — every confirmed stack decision with reason chosen AND alternatives explicitly rejected
S
.claude/steering/structure.md — proposed folder map for the confirmed stack. Evolves as project grows.
C
CLAUDE.md (generated last) — stack one-liner, conventions, NEVER list, three @import lines. No duplication of steering content.
CLAUDE.md ← generated last # Stack Node.js · Fastify · stateless # Conventions - Validate with Zod - Log with Pino - Atomic commits per task # NEVER - In-memory state - Unapproved libs - Secrets in repo See @.claude/steering/product.md See @.claude/steering/tech.md See @.claude/steering/structure.md
Why CLAUDE.md last? Writing it after the steering docs forces the skill to treat them as the source of truth and prevents duplicating context, rationale, or folder maps into the instructions file.
