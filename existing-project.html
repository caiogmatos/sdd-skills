E·02
/sdd-bootstrap
Reverse-engineers CLAUDE.md and steering docs from an existing codebase — never invents decisions
+
runs once per project commit output before next session no code written
01
Clone and scan — run git log --oneline -10, ls -la. Understand what exists before opening Claude.
02
Invoke /sdd-bootstrap — Claude scans folder structure, package files, config files, sample source.
03
Answer questions — one at a time for anything ambiguous. Claude does not invent decisions.
04
Approve 4 files — product.md, tech.md, structure.md, then CLAUDE.md (last, with @imports).
05
Commit — "chore: add SDD context files"
Output files
CLAUDE.md — stack · conventions · NEVER · @imports
.claude/steering/product.md
.claude/steering/tech.md
.claude/steering/structure.md
Key constraint: CLAUDE.md must not duplicate content from steering docs. If context, rationale, or folder maps appear in CLAUDE.md — that's a sign the skill went wrong. Push back and ask it to move those to the appropriate steering doc.
E·03
STATE.md + Hash Anchor
Generated on demand · never written manually · commit hash keeps it auditable
+
01
Read STATE.md — extract the Last commit hash
02
Run git log {hash}..HEAD --oneline — are there new commits?
03
If messages are vague — read the diff to infer what actually changed
04
Regenerate STATE.md — update hash to HEAD, mark features done/in-progress/abandoned
Why hash anchoring works with non-SDD peers: Even if a teammate pushes commits without updating STATE.md, the hash makes staleness objective — "are there commits after this hash?" is a yes/no question Claude can answer with git.
# State _Generated: YYYY-MM-DD_ Last commit: `a3f9c12` _Valid until: next merge to main_ ## Done - auth — implemented see specs/auth/ ## In Progress - queue-processor (T1-T3 done) ## Blockers - none ## Next Steps - complete T4, T5 for queue
Generate STATE.md prompt
Read CLAUDE.md, steering docs, all specs/, and git log --oneline -20. Generate STATE.md: what's done, in progress, known issues, next steps. Include current HEAD hash.
Update STATE.md prompt
Read STATE.md, extract last commit hash. Run git log {hash}..HEAD --oneline. If there are new commits, read diffs and update STATE.md. Update hash to HEAD.
