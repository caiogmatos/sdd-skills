What is SDD

Spec-Driven Development is a workflow for AI-assisted coding where no code is written until a spec is approved. Every feature starts with requirements, moves through design (including explicit stack gap detection), then breaks into atomic tasks. Claude Code executes the tasks — you review the decisions. STATE.md with a git hash anchor keeps the whole team in sync, even with peers who don't use AI tooling.

Skills overview
/sdd-startup
Greenfield only. Elicits project purpose and guides stack decisions via structured trade-off conversation.
invoke → new project, no code yet
/sdd-bootstrap
Existing codebase. Reverse-engineers CLAUDE.md and steering docs. Asks before inventing anything.
invoke → once per project
/sdd-checkup
Audits project health: context files, STATE.md drift, orphaned specs, desynced metadata. Reports first, fixes after approval.
invoke → any dormant or unfamiliar project
/sdd-feature
Requirements → Design (with stack gap detection) → Tasks. Three human approval gates before any code.
invoke → before implementing any feature
/sdd-implement
Implements one or multiple features. Audits overlap, proposes parallel worktree or sequential execution, presents plan first.
invoke → after tasks.md is approved
/sdd-validate
Verifies spec conformance, updates steering docs, marks STATE.md, updates CHANGELOG/README/package.json. Fresh session only.
invoke → after all tasks complete
