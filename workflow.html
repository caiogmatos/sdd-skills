Spec phase — RDT
R
Requirements — Claude asks questions one at a time → specs/[feature]/requirements.md. You approve.
D
Design — cross-references tech.md. Stops if stack gap found. Presents options, waits for your decision. You approve.
T
Tasks — atomic tasks with PARALLEL / SEQUENTIAL / GATE markers. You approve.

/sdd-feature [feature name]
Stack gap — example
GAP — Queue mechanism
Not in current stack. Options:
A) In-memory — zero infra
B) BullMQ + Redis — persistent
C) SQS — managed, adds AWS dep
Which fits your deployment?
Once you decide, /sdd-validate writes it into tech.md — so future features inherit the decision.
Implement phase — same session
01
Continue same session — tasks.md is already loaded. No context reload needed.
02
Tasks executed in order, atomic commit after each. Stop and correct if output drifts from spec.
03
Do not start Session 3 until all tasks are complete and committed.
Start implementation
/sdd-implement [feature name]

Validate
Spec conformance · steering audit · STATE.md · CHANGELOG · README · package.json
+
fresh session — clean context phase 1 is a hard gate can be run by another dev
P1
Spec conformance — each AC verified. Any failure stops the skill. No housekeeping until all pass.
P2
Steering audit — structure.md and tech.md updated, including stack gap decisions made during design.
P3
STATE.md — feature marked implemented or abandoned. Abandoned tasks noted with reason. Hash → HEAD.
P4
Metadata — CHANGELOG, README, package.json updated only if they exist. Semver bump confirmed with you.
Validation report
✓ / ✗ per acceptance criterion
→ steering docs: updated / no change
→ STATE.md: updated (new hash)
→ CHANGELOG: updated / not found
→ README: updated / no changes
→ package.json: bumped / skipped

Advanced — Multiple features in parallel
Parallel Feature Implementation
Spec all features first · implement simultaneously in isolated worktrees · validate after merge
SPEC PHASE (sequential — needs your approval) Session A → /sdd-feature feature-A → approve specs/feature-A/tasks.md Session B → /sdd-feature feature-B → approve specs/feature-B/tasks.md Session C → /sdd-feature feature-C → approve specs/feature-C/tasks.md IMPLEMENT PHASE (parallel — all run simultaneously) worktree/feature-A ← backend-builder agent → atomic commits worktree/feature-B ← backend-builder agent → atomic commits worktree/feature-C ← backend-builder agent → atomic commits GATE — merge each branch to main, then validate separately VALIDATE PHASE (one session per merged feature) Session X → /sdd-validate feature-A Session Y → /sdd-validate feature-B Session Z → /sdd-validate feature-C
Orchestrator prompt — /sdd-implement handles this automatically
