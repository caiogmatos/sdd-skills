S·01
Install skills and agents
One command · 6 skills into ~/.claude/skills/ · 2 agents into ~/.claude/agents/
+
re-run any time to update doesn't touch your CLAUDE.md downloads from github.com/caiogmatos/sdd-skills
Windows · PowerShell
$base = "https://raw.githubusercontent.com/caiogmatos/sdd-skills/main"
foreach ($n in "startup", "bootstrap", "checkup", "feature", "implement", "validate") {
  New-Item -ItemType Directory -Force "$HOME\.claude\skills\sdd-$n" | Out-Null
  Invoke-WebRequest "$base/skills/sdd-$n/SKILL.md" -OutFile "$HOME\.claude\skills\sdd-$n\SKILL.md" -UseBasicParsing
}
New-Item -ItemType Directory -Force "$HOME\.claude\agents" | Out-Null
foreach ($a in "sdd-implementer", "sdd-reviewer") {
  Invoke-WebRequest "$base/agents/$a.md" -OutFile "$HOME\.claude\agents\$a.md" -UseBasicParsing
}
macOS · Linux · WSL
base=https://raw.githubusercontent.com/caiogmatos/sdd-skills/main
for n in startup bootstrap checkup feature implement validate; do
  mkdir -p ~/.claude/skills/sdd-$n
  curl -fsSL "$base/skills/sdd-$n/SKILL.md" -o ~/.claude/skills/sdd-$n/SKILL.md
done
mkdir -p ~/.claude/agents
for a in sdd-implementer sdd-reviewer; do
  curl -fsSL "$base/agents/$a.md" -o ~/.claude/agents/$a.md
done
01
Run the command for your system. On Windows that puts the files in C:\Users\<you>\.claude\. In WSL, run the macOS/Linux version inside WSL. WSL has its own ~/.claude/.
02
No restart needed in most cases: Claude Code picks up new skills and agents in the running session. If ~/.claude/skills/ or ~/.claude/agents/ didn't exist before, run /reload-skills for the skills and start a new session for the agents.
03
Check the skills: type /sdd and all six should autocomplete.
04
Check the agents: ask Claude "which custom agents do you have?" It should list sdd-implementer and sdd-reviewer.
Installing by hand? Each skill must be a folder containing a file named exactly SKILL.md, e.g. ~/.claude/skills/sdd-feature/SKILL.md. The download buttons on the Skills page save files as sdd-feature-SKILL.md so they don't overwrite each other, so rename each one. Agent files keep their names: ~/.claude/agents/sdd-implementer.md.
~/.claude/ ├── skills/ │ ├── sdd-startup/SKILL.md ← /sdd-startup │ ├── sdd-bootstrap/SKILL.md ← /sdd-bootstrap │ ├── sdd-checkup/SKILL.md ← /sdd-checkup │ ├── sdd-feature/SKILL.md ← /sdd-feature │ ├── sdd-implement/SKILL.md ← /sdd-implement │ └── sdd-validate/SKILL.md ← /sdd-validate └── agents/ ├── sdd-implementer.md ← used by /sdd-implement └── sdd-reviewer.md ← used by /sdd-validate
S·02
~/.claude/CLAUDE.md
Your personal preferences · loaded in every project on this machine
+
set once, edit as you learn keep it short: it's loaded every session don't declare OS or versions
✓
Communication: one question at a time, multiple-choice questions where possible, wait for approval before executing a plan
✓
Code style: functional over OOP, explicit over implicit, no silent fallbacks
✓
Workflow: atomic commits, and show evidence (the command and its result) when claiming something works
✓
SDD: specs for features and multi-file changes, but not for one-line fixes; flag stack gaps; use agents for broad research
✗
Leave out what Claude detects itself (OS, runtime versions, package manager, shell) and project-specific rules, which go in the project's CLAUDE.md.
The install command doesn't create this file, so it can't overwrite one you already have. Copy the template, then edit the Code style section. It holds one person's preferences, not SDD rules.
Test every line: would removing it make Claude make mistakes? If not, cut it. When CLAUDE.md gets long, Claude starts missing the rules that matter.
S·03
Model selection
Opus is the default · opusplan for spec sessions · each agent picks its own model
+
✓
Opus 5.5 is the default on Pro, Max, Team and Enterprise plans. That's a good fit for the main conversation, which plans and coordinates.
✓
opusplan uses Opus while in plan mode and switches to Sonnet to execute. Useful for long spec sessions if you want to save usage.
✓
Agents choose their own model. sdd-implementer runs on Sonnet (fast and capable for one well-specified task), and sdd-reviewer on Opus (careful judgment). To change one, edit the model: line in its file.
↑
Fable 5.1 (/model fable) for your hardest, longest-running problems: large refactors and high-stakes architecture.
✗
Don't put the model in CLAUDE.md. Set it per session with /model or --model.
# start a session on a given model claude --model opus claude --model opusplan # switch mid-session (context is kept) /model # opens the picker /model sonnet # switch immediately # in an agent file's frontmatter model: sonnet # or opus, haiku, fable, inherit
inherit makes an agent use whatever model the main conversation is on. Use it if you'd rather control everything from /model.
